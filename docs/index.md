# NetBox plugins provider

Manages objects of NetBox plugins. Use it next to the `e-breuninger/netbox` provider, which manages core NetBox objects; both read the same environment variables.

Resources are named `netboxplugins_<plugin>_<model>`. Core objects (IP addresses, prefixes, tenants, tags) stay with the [`e-breuninger/netbox`](https://registry.terraform.io/providers/e-breuninger/netbox) provider and are referenced by ID; tags by name.

## Supported plugins

| Plugin | Resources | Tested with |
| ------ | --------- | ----------- |
| [netbox-plugin-dns](https://github.com/peteeckel/netbox-plugin-dns) | `netboxplugins_dns_*` | NetBox 4.6 with 1.6, NetBox 4.7 with 1.7 |
| [netbox-data-flows](https://github.com/Alef-Burzmali/netbox-data-flows) | `netboxplugins_dataflows_*` | NetBox 4.6 with 1.5, NetBox 4.7 with 1.6 |

A resource whose plugin is not installed fails with an error naming the plugin. Other versions work with a warning.

## Managed attributes

Only attributes set in the configuration are managed. An optional attribute left out takes the value NetBox holds and is never sent; removing an attribute from the configuration leaves its value in NetBox. To clear a value, set it explicitly (`""`, `[]`). For `custom_fields`, only the keys in the configuration are managed.

## Example Usage

```terraform
terraform {
  required_providers {
    netbox = {
      source = "e-breuninger/netbox"
    }
    netboxplugins = {
      source = "gluendo/netboxplugins"
    }
  }
}

# Both providers read NETBOX_SERVER_URL and NETBOX_API_TOKEN.
provider "netbox" {}
provider "netboxplugins" {}
```
